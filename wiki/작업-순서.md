[[Home]] · [[GitHub Projects 도입]]

```text
Issue 확인 → 브랜치 생성 → 작업과 중간 저장 → 테스트 후 PR → 리뷰 → Merge와 종료
```

## 1. Issue 확인

GitHub Projects에서 자신이 맡은 Issue를 확인합니다.

- 작업 내용과 완료 조건을 읽습니다.
- 모르는 내용은 작업 전에 질문합니다.
- 상태를 `Todo`에서 `In Progress`로 변경합니다.

다른 사람의 코드와 연결된다면 클래스명, 요청 경로, 입력값과 출력값을 먼저 정하고 Issue에 기록합니다.

이 문서에서는 `#12` 작업을 예시로 사용합니다.

## 2. 최신 소스에서 브랜치 생성

새로운 작업을 시작할 때마다 다음 명령을 실행합니다.

```bash
git switch main
git pull origin main
git switch -c f/12
```

- `main`에서 최신 소스를 받습니다.
- 브랜치명은 작업 종류와 관계없이 `f/Issue번호` 또는 `f/Issue번호-구현내용영어한단어요약`을 사용합니다.
- 브랜치명 예시는 `f/12-dashboard`입니다.
- `main`에서는 직접 작업하거나 Commit하지 않습니다.

## 3. 개발하고 테스트

Issue에 적힌 기능을 만듭니다. 작업이 끝나면 다음 세 가지를 확인합니다.

- 프로그램이 실행되는가?
- 요구한 기능이 동작하는가?
- 기존 기능도 정상인가?

> **테스트가 끝나기 전에는 PR을 작성하지 않습니다.**

## 4. Commit, Push, PR

테스트가 끝났다면 변경 내용을 올립니다.

```bash
git status
git add .
git commit -m "사용자 목록 GUI 추가 #12"
git push -u origin f/12
```

GitHub에서 Pull Request를 작성합니다.

```text
base: main
compare: f/12
```

PR 본문은 간단하게 작성합니다.

```markdown
- 작업 내용: 사용자 목록 GUI 추가
- 테스트 결과: 정상
- Issue: #12
```

필요하다면 Issue 코멘트에 PR 주소를 붙여 넣습니다.

## 5. 함께 리뷰하고 수정

바로 Merge하지 않고 조원들이 함께 소스를 확인합니다.

1. 작성자가 만든 기능과 코드를 설명합니다.
2. 조원들이 요구사항과 기존 기능에 문제가 없는지 확인합니다.
3. 수정할 내용은 PR 코멘트에 남깁니다.

수정할 내용이 있다면 같은 브랜치에서 수정하고 **다시 테스트**합니다.

```bash
git add .
git commit -m "리뷰 내용 반영 #12"
git push
```

수정 내용은 기존 PR에 자동으로 추가됩니다. 새로운 PR을 만들지 않습니다.

## 6. Merge하고 종료

리뷰가 끝났다면 PR을 `main`에 Merge합니다.

Issue에 완료 내용을 적습니다.

```markdown
- PR: PR 주소
- 실제 작업 시간: 2시간
- 작업 결과: 사용자 목록 GUI 추가
```

마지막으로 다음 네 가지를 처리합니다.

1. Issue를 종료합니다.
2. GitHub Projects의 상태를 `Done`으로 변경합니다.
3. 로컬 `main`을 최신화합니다.
4. Merge가 끝난 로컬 작업 브랜치를 삭제합니다.

```bash
git switch main
git pull origin main
git branch -d f/12
```

## 반드시 기억할 것

- 작업 전에는 `main`에서 Pull합니다.
- 테스트한 뒤 PR을 작성합니다.
- 함께 리뷰한 뒤 Merge합니다.
